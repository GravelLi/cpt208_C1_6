Technical Implementation

Building HerRun as a mobile-first, body-aware running web app

This page explains how HerRun was implemented as an interactive web prototype. The system translates our women-centred running concept into working interface logic, including personalised daily goals, cycle-aware running adjustment, safety support, route-based running interaction, adaptive music, and wearable-style health feedback.

Core Feature Implementation

Implemented features connected to our user requirements

HerRun implements the main playful and supportive features from our requirements, including mood-based goals, cycle-aware adjustment, safety support, music interaction, and wearable-style health feedback.

Feature 1

Mood-based daily goal

The homepage shows a flexible running goal based on the user's mood, health signal, and saved cycle record. The goal is designed to feel gentle rather than strict.

Feature 2

Cycle-aware adjustment

The Cycle Calendar lets users save today's cycle condition. The homepage then updates the goal and reminder text based on the saved record.

Feature 3

Safety support

The running page includes SOS confirmation, route status, and Match buddy interaction to make solo running feel safer and more supported.

Feature 4

Adaptive music

The music panel includes categories such as recovery, easy, tempo, and sprint. The prototype also simulates music recommendation based on heart rate.

Feature 5

Wearable-style health data

The Health Data page presents heart rate, pace, sleep, calories, recovery score, and trend information in a simple mobile dashboard.

Feature 6

Playful reward feedback

The homepage uses a Mood Star reward area to make progress feel positive and playful, instead of only focusing on speed, calories, or distance.

Technology Stack & Deployment

Free-tier web technologies used to build and publish HerRun

The prototype uses lightweight front-end technologies so that it can be hosted publicly, opened through a URL, and tested on a mobile-sized interface.

Platform

Mobile-first Web App

HerRun was developed as a web app using HTML, CSS, and JavaScript. The visual layout uses a phone-frame interface to match the mobile running context.

Deployment

GitHub Pages

The prototype is deployed through GitHub Pages, making the final system accessible through a public live URL during the marking period.

Map Service

AMap interaction

The running page uses AMap-based search, location, route display, and map interaction to simulate an outdoor running experience.

State Logic

JavaScript interaction states

JavaScript controls start, pause, finish, route status, music selection, SOS overlay, buddy matching, heart rate, pace, and cycle-based home page text.

Local Storage

Cycle record persistence

The cycle page stores the user’s selected cycle status and symptoms locally. The home page reads this record and updates the personalised goal and reminder.

Assets

Images, icons, and audio

The prototype uses custom visual assets, SVG icons, avatar imagery, and local audio files to support the playful and energetic HerRun identity.

Data Handling

How HerRun manages user input and interaction states

HerRun does not collect real medical or safety data in this prototype. Instead, it uses local records and simulated data to demonstrate how a future version could respond to users in a more personal and supportive way.

Cycle Record

LocalStorage-based persistence

When users save today’s cycle status and symptoms, the record is stored locally. The home page reads the saved record and updates the daily goal, health suggestion, mood message, and cycle reminder.

Running State

Start, pause, finish, and route feedback

The running page tracks whether the user is running, elapsed time, simulated distance, heart rate, pace, destination route, buddy status, and music state.

Safety State

SOS and buddy matching

The SOS button opens a confirmation overlay before triggering emergency feedback. The Match button changes the buddy state and gives the user a sense of social support.

Health Data

Wearable-style simulated metrics

The Health Data page uses static and simulated metrics such as heart rate, recovery score, pace, sleep, calories, and body fat rate to represent wearable integration.

Responsive & Accessibility

Mobile-first interface for running and outdoor contexts

Since HerRun belongs to the Go Runners track, the interface is designed around mobile use, quick understanding, and low-effort interaction during everyday running contexts.

Mobile-first

Phone-frame layout

The product pages use a mobile frame, scrollable main content, large rounded cards, and touch-friendly spacing to support one-handed mobile use.

Readable Controls

Text-supported icons

Key controls such as Music, Match, SOS, Start, Save, and View are supported by text labels rather than relying only on icons.

Supportive Language

Emotionally safe feedback

Health and cycle suggestions are written as gentle guidance, not medical diagnosis. Rest, walking, stretching, and light movement are treated as valid forms of progress.

Technical Reflection

AI-assisted coding prompts, verification, and ethical control

We used ChatGPT as coding support during implementation. The tool helped us scaffold interface layouts, debug interaction states, and refine wording, but the project direction, user requirements, and final design decisions remained human-led.

Prompt Examples

Prompts used for core logic and layout

Example prompts included: “Create a mobile-first running app homepage with mood-based daily goals,” “Help me make the cycle calendar save selected status and symptoms after leaving the page,” “Update the homepage text according to today’s selected cycle condition,” and “Fix the running page so Start, Finish, Music, SOS, and Match each update the correct interface state.”

AI Coding Scope

What AI helped with

ChatGPT was used to generate or refine HTML structure, CSS card layouts, responsive spacing, JavaScript state logic suggestions, localStorage debugging ideas, interface wording, mobile layout adjustment, and debugging support. It was not used to define our research findings, project motivation, or human-centred design logic.

Verification

How we checked the generated code

We manually tested whether the saved cycle record changed the homepage, whether running controls updated the correct visual states, whether SOS and Match overlays appeared as expected, whether navigation links worked, and whether the prototype remained usable on a mobile-sized screen.

Requirement Match

How we checked user requirements

We compared the implemented features with our three must-have requirements: mood-based mini missions, star-based rewards, and emotionally positive feedback. We also checked that safety support, cycle-aware adjustment, and wearable-style health feedback matched the needs identified in our user research.

Ethics

Responsible use of sensitive data

Because HerRun involves mood, menstrual cycle, safety, and health contexts, the prototype uses local or simulated data. It does not claim to provide medical advice, and its feedback is written to be supportive rather than judgmental or body-shaming.
